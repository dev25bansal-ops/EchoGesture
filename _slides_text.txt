About the Problem
Track 03
CORE MOTIVATION: Sensor Jamming & 
Progressive Degradation
In GPS-denied and hostile environments, an aeroplane 
navigates through waypoints capturing reconnaissance 
images. As it proceeds, enemy jamming causes escalating 
IMU noise, bias drift, and frame dropouts until the IMU 
sensor fails entirely.
Drift & Frame 
Dropouts
Double integration explodes 
quadratically under sensor 
noise, bias drift, and 2-second 
signal loss.
Post-Failure 
Prediction
After the final checkpoint the 
IMU dies; the aircraft must 
dead-reckon its 3D path for 5 
seconds.
CHALLENGE ABSTRACT
•  Estimate the 6-DoF trajectory (position + orientation) 
through all mission checkpoints using only degraded IMU 
streams.
•  After complete IMU failure, dead-reckon the 5-second 
trajectory to strike the target.
•  Budgets: ≤ 8 MB peak RAM, ≤ 20 ms compute per 1 s of IMU, 
single CPU thread, offline.
•  Datasets: EuRoC MAV & TUM-VI; organizer degradation script 
provided.

Data Format: Dataset Input (EuRoC IMU)
Track 03
The evaluation dataset is a zipped folder of raw IMU telemetry. Non-conforming submissions fail the automated evaluation pipeline.
INPUT SPECIFICATIONS
•  Zipped folder with raw IMU telemetry — industry-standard EuRoC MAV 
format
•  File path: imu0/data.csv
•  Delimiter: comma-separated values ( , )
•  Header line: #timestamp [ns], w_RS_S_* [rad s^-1], a_RS_S_* [m 
s^-2]
•  timestamp [ns] — 64-bit integer, nanoseconds since Unix epoch
•  w_RS_S_x / _y / _z — compensated angular velocity (rad/s)
•  a_RS_S_x / _y / _z — compensated linear acceleration (m/s², includes 
gravity)
SAMPLE INPUT — imu0/data.csv
#timestamp [ns], w_RS_S_x [rad s^-1],
w_RS_S_y [rad s^-1], w_RS_S_z [rad s^-1],
a_RS_S_x [m s^-2], a_RS_S_y [m s^-2],
a_RS_S_z [m s^-2]
1403636579758555392,0.0124,-0.0023,
0.0051,0.1241,0.0312,9.8105
1403636579763555392,0.0119,-0.0021,
0.0049,0.1235,0.0305,9.8099
… one row per IMU sample

===== PAGE 17 =====
Data Format: Required Output (TUM Pose)
Track 03
OUTPUT SPECIFICATIONS
•  File name: estimated_trajectory.txt (space-separated)
•  Header optional — commented lines must start with #
•  One estimated pose per row, exactly 8 columns
•  timestamp — floating-point seconds (Unix epoch)
•  tx  ty  tz — 3D position vector (meters)
•  qx  qy  qz  qw — normalized unit quaternion (world frame)
SAMPLE OUTPUT — estimated_trajectory.txt
# timestamp tx ty tz qx qy qz qw
1403636579.7585 0.0012 0.0045 0.0102
0.0001 0.0023 0.0011 0.9999
1403636579.7635 0.0015 0.0049 0.0105
0.0002 0.0024 0.0011 0.9999
… one pose per IMU frame
CRITICAL SYNCHRONIZATION RULES
•  Timestamp conversion: input is in nanoseconds → output in 
seconds (s = ns × 10⁻⁹).
•  Frequency mapping: exactly one pose per IMU frame — dropped or 
misaligned rows incur heavy penalties or failure.
