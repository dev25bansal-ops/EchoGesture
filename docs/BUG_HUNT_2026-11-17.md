# Bug hunt — every defect reproduced by execution

**Date:** 17 Nov 2026 (C3–C4, H6–H11 added 18 Nov)
**Scope:** the full repository — `src/`, `scripts/`, `results/`, `docs/`, and the release
tooling. Findings were found by direct inspection and by an independent fan-out audit,
then **every one reported here was re-run by me and its output pasted below**. Items the
audit raised that I could not reproduce are not in this file.

**Method:** each finding below was produced by running the code and observing the output.
Every entry carries the exact command and the actual output. Nothing here is inferred from
reading, and nothing is reported that I could not reproduce.

**Destructive reproductions:** C3 and C4 overwrite tracked artifacts, so each was run
against a verified backup and restored immediately. Both restorations were confirmed by
`md5sum -c` (C3) and by re-reading `members_detail` (C4), and both are noted in place.

## CRITICAL

### C1 — `predict()` returns a label from a clip with a hand in 1 of 32 frames

`src/main.py:221` rejects only when **zero** frames contain a hand. A clip where MediaPipe
finds a hand in exactly one frame passes the gate and is classified.

**Reproduced end to end.** I built a 32-frame clip with a real hand-bearing frame at
position 10 and handless frames elsewhere, then ran the real `predict()`:

```
source: hand present in 13 of 32 frames
rebuilt clip: hand present in 1 of 32 frames
predict() -> BREAKFAST1 confidence 0.0661
```

A label came back from one usable timestep. The 24-step resample masks 23 of 24 steps
(`mask sum over 24 resampled steps: 1`), so the classifier is answering from a single frame.

**The Android app refuses exactly this.** `CameraScreen.kt:88`:
```kotlin
private const val MIN_HAND_FRACTION = 0.15
```
1/32 = 0.031 < 0.15, so the app renders `LOW_FRAMES` and never classifies. The app and
the organizer's Python entry point disagree on the same input.

**Fix:** add a coverage floor to `predict()` matching the app's 0.15.

### C2 — a non-finite logit becomes the top-1 prediction with `confidence = nan`

`predict()` has no finiteness guard. The softmax and argsort are applied to whatever the
classifier returns.

**Reproduced with the exact arithmetic:**
```
normal   argsort(-p)[:1] = [0]
with NaN argsort(-p)[:1] = [1]   <- NaN sorts to the top
finite  logits -> probs [0.269 0.731]  finite=True
inf     logits -> probs [nan nan]      finite=False
nan     logits -> probs [nan nan]      finite=False
```
`np.argsort` places NaN first, so a non-finite member logit becomes `prediction`, and
`confidence` becomes `nan` — returned as a valid-looking result.

**Mitigating fact, measured:** MediaPipe produced **zero** NaN/Inf across 25 real clips
(`clips checked: 25 | with NaN: 0 | with Inf: 0`), so this needs a numerical fault to
trigger. It is unguarded on the scored path.

**Fix:** reject non-finite features before the ensemble.

### C3 — running `evaluate.py` overwrites the committed 85.45% artifact with a 58.53% single-model score

`scripts/ml/evaluate.py:177-201` writes `results/predictions_<split>.jsonl` and
`results/eval_summary_<split>.json` unconditionally — no `--out`, no existence check,
no refusal. Both files are **tracked**, and `eval_summary_test.json` is one of the
three sources of the headline number. The script also scores exactly **one** TFLite
file, while the shipped artifact is a nine-member ensemble, so what it writes is not
a measurement of the model the app runs.

**Reproduced, with the committed files backed up first:**

```
$ md5sum results/predictions_test.jsonl results/eval_summary_test.json
b69c2b334cbf1c49cb08821ed58bb1ad *results/predictions_test.jsonl
b277b8503f5d5b7d13df3da4b0fdac64 *results/eval_summary_test.json

$ python scripts/ml/evaluate.py --ckpt models/landmark_classifier_int8.tflite --split test
  mean 59.4%  min 40.8%  max 76.3%
wrote E:\samsung\results\predictions_test.jsonl (1249 rows)
wrote results/eval_summary_test.json

$ git diff --stat results/
 results/eval_summary_test.json |   23 +-
 results/predictions_test.jsonl | 2498 ++++++++++++++++++++--------------------
 2 files changed, 1259 insertions(+), 1262 deletions(-)
```

The committed summary was `n=1251 top1_pct=85.45`; the file on disk afterwards is
`n=1249 top1_pct=58.53`. A single command silently replaced the ensemble's score with
a single-model score and rewrote the per-clip predictions to match. Nothing errors, and
the summary keeps its schema — a later reader cannot tell which model produced it.

Both files were restored from the backup and `md5sum -c` confirms byte-identical
recovery, so the committed artifacts are currently correct. The defect is that this is
one command away from not being true.

**Fix:** require `--out`, or refuse to write over a tracked artifact without `--force`.

### C4 — the documented "FP16 (shipped)" reproduce command runs the INT8 exporter and destroys the shipped model set

`results/QUANTIZATION.md:88-89` tells the reader:

```bash
# FP16 (shipped): parity-checked against PyTorch, writes the artifact
.scratch/venv311/Scripts/python.exe scripts/ml/export_tflite_tf.py
```

That script is **not** the FP16 exporter. Its module docstring calls it "export a real

```
scripts/ml/export_tflite_tf.py:30  OUT = ROOT / "models" / "landmark_classifier_int8.tflite"
scripts/ml/export_tflite_tf.py:149-155  json.dump({...}, open(ROOT/"models"/"landmark_model_meta.json","w"))
```

The dict it dumps has keys `frames, feature_dim, classes, backbone, dim,
val_top1_int8, val_top1_float, int8_drop_pp, size_kb` — **no `members` and no
`members_detail`**. `src/main.py:92` reads `members` from that file, and its fallback
at `:96-100` requires `models/landmark_classifier_fp16.tflite`, which does not exist in
this repository. So the documented command takes a 9-member, 85.45% model set and
replaces it with a meta that the shipped entry point cannot load at all.

**Reproduced by writing exactly that key set and running the real loader:**

```
wrote single-model meta; keys = ['backbone', 'classes', 'dim', 'feature_dim',
                                  'frames', 'int8_drop_pp', 'size_kb',
                                  'val_top1_float', 'val_top1_int8']
FAILED: FileNotFoundError: No model found in E:\samsung\models
```

`models/` was restored from a backup immediately after; `members_detail` is back to 9
entries and `ensemble_test_top1` back to 0.8545.

Two further facts about the same block, both verified rather than inferred:

- The interpreter it names, `.scratch/venv311/`, **does not exist** on this machine
  (`ls: cannot access '.scratch/venv311': No such file or directory`). The venv that
  does exist is `.scratch/s3d_repro/venv311/`.
- The `pip install` line at `QUANTIZATION.md:82-83` lists `numpy
  opencv-python-headless mediapipe==1.2.2 ai-edge-litert`. The script does
  `import tensorflow as tf` at line 56. Following the documented setup exactly produces
  an environment in which the documented command raises `ModuleNotFoundError`.

I did **not** run `export_tflite_tf.py` end to end — a full TF conversion would rewrite
the shipped `landmark_classifier_int8.tflite` and the meta. What is verified here is the
file it writes, the exact dict it writes, and the loader's response to that dict.

**Fix:** point the FP16 row at the real FP16 exporter, move the INT8 command under the
INT8 row, and make the exporter merge `members_detail` instead of replacing the file.

## HIGH

### H1 — `--strict-resample` is never recorded in the checkpoint

`scripts/ml/train.py:248-250` sets a module global:
```python
if args.strict_resample:
    _F.STRICT_RESAMPLE = True
```
**Reproduced:**
```
checkpoint keys: ['backbone', 'dim', 'frames', 'model', 'vocab']
has strict_resample? False
```
And the complete set of references to the flag in the shipped code is:
```
src/features.py:68:STRICT_RESAMPLE = False        (definition)
src/features.py:221:  Set `STRICT_RESAMPLE = True` (docstring)
src/features.py:239:    if STRICT_RESAMPLE:        (use inside _resample)
scripts/ml/train.py:249:        _F.STRICT_RESAMPLE = True
```
Nothing in `src/main.py`, `evaluate.py`, `make_predictions.py` or `eval_tflite_cache.py`
reads it. A model trained with `--strict-resample` would be evaluated and shipped with
`STRICT_RESAMPLE=False` — different features than it learned, with no error. No shipped
checkpoint used the flag, so no current artifact is wrong; the hazard is for the next run.

**Fix:** persist the flag in the checkpoint and have the exporter refuse a mismatch.

### H2 — a bad cache path or split reports `0.00%` instead of failing

**Reproduced:**
```
$ python scripts/ml/eval_tflite_cache.py --cache /nonexistent --split test --out ...
scored 0 clips from C:/Program Files/Git/nonexistent/test (skipped 0 with no hand) in 0s
  ENSEMBLE (mean-logit): 0.00%
n = 0 | ensemble_top1_pct = 0.0
```

A typo in the cache path or split name writes a well-formed artifact claiming a 0% model.
Verified for both a missing directory and a bogus split name.

**Fix:** exit non-zero when `n == 0`.

### H3 — an unreadable video is reported as "No hand detected"

**Reproduced on three malformed inputs:**
```
$ python src/main.py /tmp/fake.mp4      # a text file named .mp4
ValueError: No hand detected in any frame of: .../fake.mp4
$ python src/main.py /tmp/empty.mp4     # zero bytes
ValueError: No hand detected in any frame of: .../empty.mp4
```
The cause is that `read_frames` returns `[]` with no exception:
```
/tmp/fake.mp4  read_frames -> []
/tmp/empty.mp4 read_frames -> []
```
The message sends the user to debug their *video content* when the file itself is
unopenable. (An earlier probe also confirmed an empty file and a zero-byte `.avi` behave
the same way.)

**Fix:** distinguish "could not decode" from "decoded but no hands".

### H4 — "worst-case drop" can never report an improvement

`scripts/ml/robustness.py:251-261` initialises `worst = 0.0` then `max(worst, drop)`.
**Reproduced with the exact code path:**
```
corruption     drop    worst
blur          +1.00    +1.00
jpeg          -3.00    +1.00
reported worst: +1.00
true minimum : -3.00
```
A corruption that *raises* accuracy by 3 points is reported as a 0.00 drop. The rubric
verdict is unaffected (it can only overstate a failure), but the diagnostic is blind to a
corruption that helps — which is how you'd spot a badly-formed corruption.

### H6 — `hf_upload_all.py` uploads `.git` and 88,830 `.cache` files it was written to skip

The module docstring states the intent (`scripts/release/hf_upload_all.py:7-8`):
*"Deliberately skips: `.git/` — history is not what was asked for, and it is large"*.
`SKIP_PATHS = {".cache"}` is declared at line 34 — and never referenced anywhere in the
file (`grep -n SKIP_PATHS` returns only the definition). `collect()` prunes on
`SKIP_DIRS` and `is_venv()` only, and `is_venv()` is hardcoded `return False`.

**Reproduced with the real `collect()`:**

```
$ python scripts/release/hf_upload_all.py --dry-run
files to upload : 184,421
bytes           : 16,980,161,085 (16.98 GB)

$ python -c "from hf_upload_all import collect; f,s=collect(Path('.')); ..."
total files : 184421

                '.cache/huggingface/upload/.gitignore.metadata']

```

`.cache` is 48% of the whole selection. Two consequences worth separating:

- **Volume.** 88,830 files of the Hugging Face client's own staging area get pushed into
  the dataset repo — the client duplicating its staging tree into itself.
- **History.** `.git/` carries the 11 restricted weight files that `NOTICE` and
  `docs/release/ARTIFACT_RIGHTS.md` mark "BLOCKED for publication". Pushing `.git/`

I checked `.git/config` for embedded credentials — the `url` line is
`https://github.com/dev25bansal-ops/EchoGesture.git` with no token, so the upload does
not leak a PAT. That is the only part of this finding that came back clean.

**Fix:** reference `SKIP_PATHS` in `collect()`, and add `.git` to it.

### H7 — the resume check keys on batch ordinal, so a second push of new files uploads nothing

`scripts/release/hf_push_for_pod.py:114-117`:

```python
for bi, batch in enumerate(batches, 1):
    key = f"{rel}#{bi}"
    if key in done:
        print(f"[{gi}/{len(PLAN)}] {rel} {bi}/{len(batches)} - done")
        continue
```

The key contains the group name and the batch **index** — not the file list, not a
content hash. If the set of files changes but the batch count does not, every batch looks
already-done.

**Reproduced by executing the script's own `main()` against a temp tree twice**, with
`huggingface_hub.HfApi.upload_folder` stubbed to record calls, and a state file carried
over from run 1:

```
RUN 1: uploaded batches = 8 | state keys = 8
RUN 2: uploaded batches = 0 | files present = 18
```

Run 2 had 18 brand-new files with different names throughout; it uploaded none of them
and printed `- done` for all eight batches. The state keys are literally
`.scratch/landmarks#1`, `models#1`, `src#1`, … — nothing about what was in them.

**Fix:** key the resume state on the batch's file list or a digest, not its ordinal.

### H8 — `assemble.py` and the three `window_*.py` scripts feed features into the mask input

The TFLite converter emits the mask as input 0 and the features as input 1. Four scripts
bind to `get_input_details()[0]` and never look at the name:

```
scripts/ml/assemble.py:79-80        it.set_tensor(ii, f[None]...)
scripts/ml/window_validate.py:45    it.set_tensor(ii, feats[None]...)
scripts/ml/window_sweep.py:43       (same binding)
```

**Reproduced against a real shipped member:**

Every one of these scripts dies on the first clip against any current member.
`src/main.py` and `scripts/ml/evaluate.py` both resolve inputs **by name**, with a

**Fix:** use the same name-based resolver.

### H9 — `compare.py`, `sweep.py` and `ensemble.py` cannot load any `_z` member

`TemporalModel.__init__` takes `in_dim=FEATURE_DIM` (`scripts/ml/train.py:67-68`), and its
own comment says the width "is not a constant: the `use_z` ablation widens it from 255 to
381". The three call sites omit it:

```
scripts/ml/compare.py:48    m = TemporalModel(len(ck["vocab"]), dim=int(ck["dim"]), ...)
scripts/ml/sweep.py:85      (same)
scripts/ml/ensemble.py:57   (same)
```

**Reproduced on a real shipped `_z` checkpoint:**

```
ckpt dim 192 frames 24 backbone tcn
stem.weight (192, 381, 1) -> in_dim 381
COMPARE.PY STYLE FAILED: RuntimeError Error(s) in loading state_dict for TemporalModel:
	size mismatch for stem.weight: copying a param with shape torch.Size([192, 381, 1])
	from checkpoint, the shape in current model is torch.Size([192, 255, 1]).
WITH in_dim: loaded OK
```

All five `_z` members are 381-wide (confirmed from the shipped TFLite input shapes), so
the ensemble-comparison tooling cannot open 5 of the 9 models whose comparison it exists
to report.

**Fix:** pass `in_dim=int(ck["model"]["stem.weight"].shape[1])`.

### H11 — `evaluate.py`'s own two documented invocations both fail

`scripts/ml/evaluate.py:92` defaults `--ckpt` to `models/landmark_classifier_fp16.tflite`,
which **does not exist** in this repository (the shipped set is the nine
`landmark_ens_*_fp16.tflite` members). The usage docstring at line 20 suggests
`--ckpt .scratch/runs/model.pt`.

**Reproduced, both paths:**

```
$ python scripts/ml/evaluate.py --split test
ValueError: Could not open 'E:\samsung\models\landmark_classifier_fp16.tflite'.
The model allocation is null/empty

$ python scripts/ml/evaluate.py --ckpt .scratch/runs/model.pt --split val
ValueError: The model is not a valid Flatbuffer buffer
```

The default fails because the file is absent; the docstring path fails because it hands a
PyTorch checkpoint to a TFLite interpreter. `load_classifier()` only ever opens one
`.tflite`, so **no** invocation of this script scores the shipped nine-member ensemble —
which is what turns C3 into real damage, since the script writes its single-model result
over the ensemble's committed artifact.

**Fix:** default `--ckpt` to the ensemble, or drop the flag and read `members_detail` the
way `src/main.py` does.

### M4 — `app_path_eval.json` silently omits two scorable native-cache clips

The artifact says `n=1249, nodet=0`, and its `per_clip` list has 1,249 entries. The
native test cache has 1,255 files. Comparing IDs gives six missing clips:

```
009924818599383212-COMB       present=0/32  prediction absent
07428079785719932-FOREIGNER   present=0/32  prediction absent
2082336345836704-DECIDE       present=0/32  prediction absent
4993288821586179-ANYONE       present=0/32  prediction absent
45888619089929517-DEMAND      present=7/32  prediction in predictions.jsonl
```

The full 1,249-video app-path rerun was started to independently confirm the resulting
score but timed out after 10 minutes and was stopped. Therefore I **do not claim a
recomputed app_path accuracy** here; the confirmed defect is the silent 6-clip accounting
mismatch and its exact root cause. The stored artifact's 85.5084% is not a full-native-
cache score, and the quoted "per-clip identical on 1,249/1,249" check compares only the
1,249 IDs selected by the old cache.
