# Audit of this session's own work, 15 Nov 2026

Two independent reviewers audited the six documents written this session and the
uncommitted code changes. Twelve findings came back. **All were real.** They are
recorded here because a session that produced several wrong numbers should leave
a trace of what was wrong and how it was caught.

## The most serious: a significance test attributed to the wrong measurement

`GEOMETRY_FINDING.md` presented a McNemar result (49 vs 97, z=3.89, p=0.0001)
directly under a table whose headline row was the **native 640×480** path at
85.51%. But that test came from `geometry_pair.json`, whose `app640x480`
geometry is **640 letterboxed to a square** — the approximation I used before
wiring the native path. The native path had no test at all.

Recomputed correctly, on the same 1,249 clips:

| | |
| --- | --: |
| squash256 only right | 52 |
| native 640×480 only right | 90 |
| McNemar z | 3.10 |
| p (two-sided) | **0.0019** |

Still decisive, but it is not p=0.0001 and a reader was being handed the wrong
statistic. Fixed in the document, with both tests now stated and distinguished.

## Code findings

- **`results.csv` cited a command that does not run.** It gave
  `robustness_pixel_parallel.py --level pixel`, but that script has no `--level`
  argument — the cited reproduce command exits with "unrecognized arguments".
- **Parallel harness defaulted to a different geometry than serial** (512 vs
  256), so an unqualified run silently scored a different experiment.

Both fixed. Default-path drift was checked and **no defect found** — `read_frames()`
with no arguments is byte-identical to the old 256-squash path, `FRAME_SIZE` is
256, and `ensemble_probs` matches `src/main.py` to 1e-12.

## Claims that had no stored artifact

The auditor was right that several numbers existed only in terminal output. Both
are now stored: `results/cache_gap_decomposition.json` reproduces the cached-side
column exactly (63.4615% on the 364 differ clips, 82.4859% on the 885 agree
clips, with per-clip flags), and `results/cache_presence_by_split.json` holds the
train/val/test rates.

Still unsupported by any stored file, and flagged as such in their documents:
the Kotlin/Python feature-parity diffs, the low-light presence/CLAHE/gamma
measurements, and the 5.55 s/clip timing.

## What this says about the session

Every one of the twelve was found by an independent reader, not by me. The
pattern is consistent: I measured real things, then described them in prose that
drifted from what the files said — a test attached to the wrong row, a
comparison inherited across a changed baseline, a stale footer left behind by a
later run. The measurements held up under audit; the sentences around them did
not.
